# cloud 模式详解(账号池)

把一批 Claude 账号做成跨机器共享的池子:一台 **master** 持有全部 refresh token 并作为**唯一的刷新者**,多台 **worker** 向它租借短时效 access token。配置写法与运维步骤见 [README](../README.md);架构决策的完整记录与实测证据见 [design/cloud-mode-adr.md](design/cloud-mode-adr.md)。

## 职责划分

| | master | worker |
|---|---|---|
| refresh token | 持有**全部**账号的真实 refresh | **永不持有可用的 refresh** |
| 刷新 | **唯一的刷新者**,单飞(同账号并发只发一次刷新请求) | 从不刷新,只领租 |
| 选号 | 按各账号订阅用量挑最空的,维护冷却状态 | 不参与选号 |
| 撞限检测 / 续接 | 看不到(429 只在 worker 的会话事件里) | 检测 429、上报 master、拿到新号后续接那一轮 |
| 推理 | 不跑 | 跑 |
| ChatGPT | 不纳入池子 | 仍走本地 codex 插件 |

## worker 的 `auth.json` 里那个奇怪的 refresh 是什么

如果你在 worker 上打开 `auth.json`,会看到 `anthropic` 条目的 `refresh` 是一串**明显不像 token 的常量**。这是故意的。

实测发现 **OpenCode 会静默丢弃缺少 `refresh` 字段的 `anthropic` 条目**:带一个假值时 `opencode auth list` 报 `1 credentials`,去掉该字段就变成 `0 credentials`,而且退出码 0、一句报错都没有。所以租约只能写成 `access` + `expires` + 一个**可识别的哨兵字符串**。

账号库的收录路径会**按值拒绝**这个哨兵,因此它永远不会被误当成真凭据存起来、也不会被回传给 master。这个守卫是按值判断而非按模式判断的,所以在 local 模式下这条分支永远不会被走到。

## 为什么租约的到期时间比账号 token 的真实到期更早

master 会在账号 token 即将过期前把它刷新掉,而**这次刷新会立刻作废上一枚 access token**(实测:旧 access 刷新前 `200`,刷新后同一枚 `401`)。这违反常规 OAuth 2.0 语义,却是实际行为。

所以 master 下发租约时,故意把到期时间**封顶在自己动手刷新的那一刻之前**,worker 再提前一段续租——这样 worker 永远在 master 轮换之前就换到了新 token。若租约视界已经落到过去,master 直接拒绝发放(返回"暂无可用账号"),而不是下发一枚到手即死的 token。

万一 worker 仍然握着被轮换掉的 token(时钟偏移、笔记本休眠唤醒),它会把 `401` 当作"租约被轮换"处理:立刻重新领租并续接那一轮,**不会**把这个健康账号误判成撞限而冷却掉——把 401 误 route 进限流路径会白白冷掉一个好号、削减池子容量。

## 为什么内部标识符仍然叫 `claude-accounts-usage`

包名改成了 `claude-accounts-pool`,但代码里的内部标识符**一律保持原样**。这是刻意的,**请不要"顺手统一"**:

- **跨进程锁文件名 `claude-accounts-usage.lock`** —— 这把锁防的正是"两个插件实例并发轮换同一张一次性 refresh token"。如果某台机器上新旧两个包同时存在而锁名不同,**互斥会直接消失**,而这正是整个项目要避免的那个失败。
- **OpenCode 的 KV 命名空间** —— 已签发的 pool key 存在里面,改了会全部孤立。
- **日志服务名** —— 所以 README 里那条 `grep` 命令不变。
- **租约哨兵字符串** —— 改了两个版本就互不认识对方的租约。

## pool key

- 每台 worker 一把。**常规路径是自助领取**:在看板上点「领取 key」,填一个这台机器的 label,当场签出。master 那个 OpenCode 会话里的 `/reg` 命令**保留为兜底**——端口只绑了 loopback、或者你人已经在 master 的终端里时还有一条路,它记下的 label 固定是 `tui`。两条路签出的 key 完全等价。
- **明文只显示一次**,库里只存 SHA-256 摘要;校验用常量时间比较(lease 端点是个在线 oracle,对摘要做朴素 `===` 是计时侧信道)。
- **有效期 7 天,每次成功租借向后滑一次**,见下文。
- 编号从**已发出的最大号 + 1** 推导,而不是从当前条目数——否则吊销一台 worker 留下编号缺口后,下一次签发会重用编号并**静默覆盖**另一台在用 worker 的摘要。过期回收同理:**腾出来的编号不回收**,签发时数的是过期清理**之前**那份快照的最大号。
- `/v1/health` 是**免鉴权**的就绪探针,`/v1/lease` 与 `/v1/ratelimit` 都要求 `Authorization: Bearer <poolKey>`;请求体里的 `workerId` 只作参考,**身份一律由 key 决定**(信任请求体等于可被伪造)。看板那几条路由——包括签发 key 的那条——都免鉴权,理由见下文。

### key 会过期了:7 天,滑动

以前一把 key 是**永久**的:一年前粘进某台笔记本 `tui.json` 的 key,今天照样开得了池子,而且全系统没有任何吊销入口。现在它是**租**来的:

- **7 天**(`POOLKEY_TTL_MS`),签发即起算。
- **每一次成功校验都把到期时间滑到 `now + 7 天`。** worker 每 30 秒查一次自己的租约,到期前自动续租(撞限换号、面板上手动切号同样走 `/v1/lease`),所以**只要那台机器还在用,key 就不会过期**;放假一周合上笔记本回来也还在——7 天这个长度就是照着这件事挑的,再短就得考虑假期。
- 真正会消失的是**领了没用上的**:自助签发难免签出用不上的 key,7 天后它自己不见,不需要任何人记得去清理。
- 过期的 key **先被拒绝,再从库里剪掉**(顺带把同时超时的兄弟条目一并清掉)。顺序是刻意的:先拒绝,才使得"已经不在库里的条目本来就已经不可用"成立,上面那条编号不变式因此不会被过期削弱。

**滑动的落盘被限流到每小时最多一次**(`POOLKEY_SLIDE_MIN_INTERVAL_MS`)。不限流的话,每一次校验都要写一遍 kv,等于把一次租借变成一次写盘;代价是**记录里的到期时间最多比真实值滞后 1 小时**——占 7 天窗口约 0.6%,滑动本来就留着 7 天余量,这点滞后吃不掉它。上一次滑动的时刻不单独存,由 `expiresAt - 7 天`**推出来**,记录因此保持四个字段不变。

### 库里存的不再是一条摘要

KV 条目 `claude-accounts-usage.master.poolkeys` 的值换了形状:

| 以前 | 现在 |
|---|---|
| `{"worker-1": "<sha256 摘要>"}` | `{"worker-1": {"digest": "<sha256 摘要>", "label": "laptop-1", "issuedAt": <毫秒>, "expiresAt": <毫秒>}}` |

**升级不会踢掉正在跑的 worker。** 遗留的裸摘要条目在**升级后第一次用到注册表时**(第一次租借校验、第一次签发、或者 master 启动时数一下有几把 key,谁先来算谁)被**整份就地改写**成新形状,摘要**逐字保留**——那台 worker 手里的 key 原样有效。迁移只在真的读到裸摘要时才写一次,不是每次启动都写。

两个跟着来的事实:

- 它的 label 记成 `legacy`。旧形状里根本没记过是哪台机器领的,写别的都是编。
- 它的 7 天**从迁移那一刻开始算**,不从当初签发那天倒推。旧记录里没有签发时间,拿一个猜测去倒推,等于让一台在跑的 worker 在升级瞬间掉线。之后照常随每次租借滑动。

手工编辑过这个条目的人请照新形状**把四个字段写全**:缺 `expiresAt` 的记录行为并不一致——校验时的比较会落到 `undefined` 上而放行,但任何一次过期清理又会把它剪掉,不要指望它。

### 手工改 KV 之前必须先停掉 master

这是目前**唯一**能吊销一把还活着的 key 的办法,所以它出错的代价最大。顺序只有一种:**停服 → 改文件 → 起服**。

对着运行中的 master 改 `kv.json` 会踩两个坑,**两个都实测过**:

1. **改了不生效。** OpenCode 的 KV 在进程里有一份内存副本,注册表每次校验读的是它,不是磁盘。把某个 `worker-N` 从文件里删掉之后,那把 key **当场照样租得到号**。
2. **改了会被悄悄撤销。** `set` 是把内存里那份整个写回磁盘。所以 master 下一次写 KV(有人领了新 key、某把 key 滑动落盘)就会把你删掉的条目**原样写回来**。

两条合起来是吊销场景里最坏的一种失败:操作的人以为凭据已经作废,它却一直有效,而且文件看上去还"改成功了"——直到下一次写入把它变回去。**这不是配置讲究,是这条路径的正确性前提。**

### 一条命令把 worker 配好

签完 key,看板同时给出一条能直接粘进那台 worker 终端的命令:

```bash
git clone --depth 1 https://github.com/Daiwenxi798673133/claude-accounts-pool.git ~/.claude-accounts-pool \
  && cd ~/.claude-accounts-pool && bun install && bun run build \
  && bun run scripts/configure-worker.ts --master <MASTER_URL> --key <POOL_KEY> --worker <LABEL>
```

`bun` 是**硬前置**:`dist/` 不入库,worker 必须本机构建一次。`configure-worker.ts` 写进配置的插件路径是**从脚本自己的位置推出来的绝对路径**(不是 cwd,也不留 `~`),指向刚构建出的那个 `dist/tui.js`。

它改的是这台机器上**别人已经配好、并且正在用**的 OpenCode 配置(`$XDG_CONFIG_HOME/opencode`,没设就是 `~/.config/opencode`),所以整个脚本是围绕"**不要弄坏它**"排的:

- **只保证两件事**:`@ex-machina/opencode-anthropic-auth` 出现在 opencode 配置的 `plugin` 数组里;本插件的 `["<clone>/dist/tui.js", {"mode": "cloud-worker", "masterUrl": …, "poolKey": …, "workerId": …}]` 元组出现在 `tui.json` 的 `plugin` 数组里。ex-machina **以任何形式出现都算数**,包括 `…@1.2.3` 这样的版本锁——重写别人的版本锁不是这个脚本的事,而再追加一份没锁的会把插件装载两遍。
- **绝不触碰、也不重排别人的条目**:插件的加载顺序是可观测的。我们自己那条(按**形状**认:路径带 `claude-accounts-pool` 且以 `dist/tui.js` 或 `tui.tsx` 结尾——clone 会换机器,用户也可能直接指源码)是**就地替换**,不是追加。
- **语义没变的文件一个字节都不碰。** 改动判定拿的是**规范化之后**的两份 JSON 比对,不是比原文,所以重跑一遍是真正的 no-op,也不会顺手把别人的缩进"修正"掉。
- **先探 `.jsonc` 再探 `.json`**(前者才是 OpenCode 自己发的那份的名字),两个都不存在时新建 `.json`。
- **写前备份**(`<原文件>.bak-<时间戳>`)、**原子写**(先写同目录临时文件再 rename,权限 `0600`),并且先把 diff 打在终端上再动手。`--dry-run` 只打 diff,不备份也不写。

四种情况它**拒绝写**,改为把该手工粘贴的 JSON 打出来(退出码 `1`)。而且**两个文件是一起规划、一起写的**:先攒齐所有问题再报,绝不留下一台配了一半的机器。

| 拒写条件 | 为什么不猜 |
|---|---|
| 文件解析不出 JSON | **`.jsonc` 里真写了注释就属于这一类**——脚本用的是 `JSON.parse`,不认注释 |
| `plugin` 存在但不是数组 | 这份配置我们看不懂,看不懂就不能改 |
| `.json` 与 `.jsonc` 同时存在 | 写哪一份都会让机器上留着两份配置,而且无从判断谁生效,得先由人删掉一份 |
| 发现旧包 `claude-accounts-usage` 的条目 | 两个插件**绝不能并存**,丢哪一个是人的决定,不是脚本的 |

参数缺失、`--master` 不是 http(s) URL 之类的用法错误退出码是 `2`,并且**一次报全**所有缺的 flag——操作者粘的是别人给的命令,一次发现一个要求本身就是个 bug。写完要**完全退出并重开** OpenCode。

## 只读用量看板

master 在**同一个端口**上多挂几条路由,给运维一个能看**全池**用量的出口——worker 和 local 模式都没有这个视角。名字里的"只读"如今只覆盖前两条,后面三条都会写(见文末的硬约束)。

| 路由 | 方法 | 鉴权 | 内容 |
|---|---|---|---|
| `/v1/usage` | GET | **免鉴权** | 全池每个 anthropic 账号的 label、id 前缀、各窗口利用率与 `resetsAt`、冷却状态、token 到期、`needsReauth` / `excluded` |
| `/` | GET | **免鉴权** | 一个零依赖的 HTML 页面,自己去拉 `/v1/usage` 并渲染(进度条 + 倒计时)。页面本身不含任何数据 |
| `/v1/usage/refresh` | **POST** | **免鉴权** | 页面上「刷新」按钮打的那一发:立刻跑一轮采集,再返回采集结果。**服务端 30 秒最小间隔**,被拒时返回 `429` + `Retry-After` + `retryAfterMs` |
| `/v1/account/authorize` | **POST** | **免鉴权** | 「添加账号」第一步:生成一条 Claude PKCE 授权链接,返回 `{url, pendingId, expiresAt}`。verifier 只留在 master 内存里,浏览器只拿到 `pendingId` |
| `/v1/account/add` | **POST** | **免鉴权** | 第二步:用运维粘回来的 code 换取真实 token,查 profile,写进账号库。返回 `{idPrefix, label, existing}`,**不含任何 token** |
| `/v1/worker/register` | **POST** | **免鉴权** | 「领取 key」:收一个 worker label,签一把 pool key,返回 `{workerId, poolKey, label, expiresAt}`——**明文只在这一次响应里出现**。全服务端 **10 秒**最小间隔,超频 `429` + `Retry-After` + `retryAfterMs`;活着的 key 满 **32** 把时 `409` `registry full` |

关于刷新按钮有两处不是随手写的:

- **必须是 POST。** 这是唯一一条会向机器外部发请求的看板路由(它让 master 逐个账号去调 Anthropic),而浏览器、链接扫描器、聊天软件的链接预览都会**主动 GET** 它们看到的 URL。做成 GET 就意味着"把看板链接贴进群里"能触发全池上游流量。
- **节流是全服务端共享的,不是按调用方。** 它保护的是 master 那一个出口 IP,所以别人按过之后你也要等——这正是正确行为。它复用 `usagePoller` 自己的 `tickOnce`,因此顺带继承了重入防护、账号间 500ms 间隔和单账号 429 冷却。

### 为什么这几条路由是裸的

这是**池主人的显式决定,推翻了本功能最初「看板不应裸奔」的要求**。当初的理由是载荷纯只读、不含任何凭据,读到它的人最多知道"池里有哪些号、各自还剩多少"。**这个理由如今只覆盖 `/v1/usage` 和 `/`**:看板后来长出「添加账号」、又长出「领取 key」,免鉴权这个决定一路沿用了下来,支撑它的东西却已经从"读不到什么"换成了"『打开网页点一下』必须成立"。

代价是真实的、明知而接受的,而且**这一次变大了**——不打算含糊过去:

- **以前**:能连到这个端口的匿名者能枚举整个池子(包括账号邮箱),能把**他自己的**号加进来,但**加进来也拿不走**——租借要 pool key。
- **现在**:他能点「领取 key」,**给自己签一把真能租借 access token 的 key**。也就是说,能连到 lease 端口,基本等于能用这个池子里的号。

绑定地址由运维决定,而且**通常不是 loopback**(本项目的部署里绑的是 tailnet 地址)。想收窄,**能收窄的依旧只有绑定地址**——默认 `127.0.0.1`,想更宽必须在 `tui.json` 里显式写 `hostname`。给这几条路由加 key,等于取消"打开网页点一下",那正是池主人不要的东西。

对照着看不该被这个决定波及的部分:`/v1/lease` 和 `/v1/ratelimit` **依然要求 pool key**。但这句话现在的分量小了一截——它不再意味着"匿名者签不出凭据",而只意味着"**匿名者得先在这台 master 的注册表里留下一条记录**才租得到号"。那不是一道安全边界,是一点**可见性**:每一把签出去的 key 都在 kv 里留了 label 和签发时间(要看得手工翻——还没有列出已发 key 的入口)。

### 「添加账号」为什么也是裸的

两条纳管路由沿用了同一个决定,同样是**池主人拍板的**:加 key 就意味着浏览器里要先输一次 key,"打开网页点一下"这件事就不成立了。但必须把话说明白——**这是看板第一次出现「会写」的路由**,原先"纯只读"那条承诺到此为止(下面的硬约束列表已相应修订)。

代替 key 的是三道**有界性**,都在 `src/constants.ts`:

| 约束 | 值 | 挡住什么 |
|---|---|---|
| `ONBOARD_MAX_PENDING` | 4 | 内存。匿名狂刷 `/authorize` 的代价是**常数**,不是慢性泄漏——满了就淘汰最旧的 |
| `ONBOARD_MAX_ATTEMPTS` | 3 | 单个会话能引发的**上游 POST 次数**。用完即焚,必须重新拿链接 |
| `ONBOARD_ADD_MIN_INTERVAL_MS` | 3 秒 | 上游 POST 的**速率**。防止一串慢速请求变成打向 token 端点的 400 风暴——那会让 master 的出口 IP 被封,连坐全池的 refresh |

**没有被声称的是**:匿名者加不了号。**他能**——只要他有自己的 Claude 账号,又连得到这个端口。收窄它的依旧是**绑定地址**,和 `/v1/usage` 完全一样。反过来说,他加进来的是他自己的号。<br>*(原文这里还跟着一句「而且**拿不走任何东西**:租借仍然要 pool key」。「领取 key」上线后这句不再成立——他现在能自己签一把 key 把号拿走,见下一节。)*

还有两点是刻意的:

- **verifier 绝不出机器。** 授权链接里带的是 challenge(verifier 的 SHA-256),浏览器只拿到一个不透明的 `pendingId`。所以就算有人截走了 code,也换不到 token——**只有 master 换得到**,这正是"master 是全系统唯一持有 refresh token 的人"这条性质的延续。
- **新链条直接写账号库,不过 auth.json。** 这条链是我们自己刚换来的,池外没有第二个持有者,所以不存在 `makeOnboardingCapture` 那边必须回避的轮换竞争;走 auth.json 反而要等 keeper 下一个 tick(最多 5 分钟)才入池,对话框只能干等或者撒谎。

### 「领取 key」为什么也是裸的

同一个决定的第三次沿用。这次交出去的是**凭据本身**——一把真能租到 access token 的 key——所以代替 key 的那几道界比前两次更该被看清楚:

| 约束 | 值 | 挡住什么 |
|---|---|---|
| `REGISTER_MIN_INTERVAL_MS` | 10 秒 | **速率**,全服务端共享而非按调用方。签发是池子里唯一会**增长**持久状态的操作,没有这道底线,这条路由就是一个对着 kv 的无限写循环。这个值是照着"人往配置里粘一次 key"挑的,不是照着脚本 |
| `REGISTER_MAX_LIVE_KEYS` | 32 把 | **总量**。它让注册表的大小是个**常数**,而不是调用方说了算。远高于任何真实规模的机器数,正常运维撞不到 |
| `POOLKEY_TTL_MS` | 7 天 | **时间**。上面那 32 把数的是**活着的** key——签了不用的会自己过期、自己被剪掉,所以刷出来的条目不会永久占着名额,库也不会被一次性刷满之后再也回不来 |

这三道界**都不声称匿名者签不出 key**。他签得出,见上一节。它们保证的只是:签发这件事不能被拿去把这台 master 的 kv 写爆或者塞满。

另外三处是刻意的:

- **满库返回 `409` 而不是 `429`。** 两者对调用方的含义不同:`429` 承诺"等一会儿这一模一样的请求就能成功",而满库不是——得有人退掉一把,或者某把没人用的自己走完 7 天。合并成节流会让浏览器对着一堵墙重试。
- **label 的口径很窄**:去掉首尾空白后必须匹配 `^[a-z0-9_-]{1,32}$`,中文、空格、大写都会被 `400` 挡回来。宽松一点会更好用,但这个 label **会被存下来,并且会渲染回那张免鉴权的页面**——放开它等于给匿名者一个写进运维视野的入口。`{1,32}` 的下界顺带让空 label 不需要单独判一次。
- **节流的时间戳在读请求体之前就打了。** 所以一次 label 写错的 `400` 同样会吃掉那 10 秒。这是为了让双击按钮不能从窗口里溜过去第二次签发——顺序反过来,代价就是可以被绕开的节流。

### 几条实现上的硬约束

- **绝不输出 token。** 载荷类型里根本没有能放 `access` / `refresh` 的字段,想泄露必须先加字段——那正是 review 会看到的地方。账号 id 只给前 8 位。**这条在免鉴权之后更要命**:前面已经没有 key 挡着了。<br>页脚那句「本页不展示任何 token 明文」说的是 **Anthropic 的 token**,它仍然成立。新签出的 pool key 是**这个池子自己的**凭据,它确实会明文出现——只出现一次,且库里只有摘要。两件事不要混。
- **不新增任何对外部 API 的轮询。** 看板读的是 `usagePoller` 已经在跑的那份快照,所以刷新页面**不可能**触发 `/api/oauth/usage`(它的 429 会持续好几分钟,且按出口 IP 连坐)。既然路由是裸的,这条也是**匿名请求打不动这个池子**的保证。<br>**「添加账号」是这条的唯一例外**,而且是有界的例外:它只在运维粘回 code 时打一次 token 端点(不是 usage 端点),次数被 `ONBOARD_MAX_PENDING × ONBOARD_MAX_ATTEMPTS` 封顶、速率被 `ONBOARD_ADD_MIN_INTERVAL_MS` 封顶。**光看页面、光点「添加账号」不会产生任何上游流量**——生成链接是纯本地的 crypto。
- **master 刚重启的 5 分钟内看板是空的。** `usagePoller` 用 `setInterval`,首轮采集要等一个 `MASTER_USAGE_POLL_INTERVAL_MS`(5 分钟),此时 `at` 为 `0`、`stale` 为 `true`,页面会明说"尚未完成任何一轮轮询",而不是画一堆 0%。
- **陈旧判定由调度器给。** 阈值就是调度器自己停止按用量排序的那条线(两个轮询周期),所以看板亮绿灯的时刻和调度器仍然信任这些数字的时刻**天然一致**;快照陈旧时页面顶部会红字明示,而不是继续画一根自信的绿条。
- **没拿到快照的账号显示「本轮无数据」,不是 0%。** 轮询失败的账号被 poller 直接省略,把这种缺失渲染成 0% 会让运维一眼看到"最空的号"其实是"最不知道的号"。
- **绑定地址沿用 lease server 的约定**:默认 `127.0.0.1`,想更宽必须在 `tui.json` 里显式写 `hostname`。这个端口本来就在发活的 access token,看板不降低它的默认。
- **会写的只有「添加账号」和「领取 key」两处,而且都不会动到在用的东西**:不切号、不删号、不改谁在用;签 key 只往注册表里加一条,顺带清掉已经过期的,**活着的条目一个都不碰**。<br>*(这句话已经被推翻过两次。原文是无条件的「纯只读」;加入纳管入口后改成「除「添加账号」外纯只读:不切号、不删号、**不签 key**」——而签 key 恰恰是看板现在做的事。两次痕迹都留着,是因为一句好听但已经不对的承诺,比没有承诺更危险。)*

## worker 的 `/usage`:选号、切号、刷新

cloud-worker 上的 `/usage` 渲染的是 master 那份同样的快照(经 `GET /v1/usage`),**worker 自己从不调 Anthropic 的 `/api/oauth/usage`**——否则 N 个 worker 就是 N 倍上游流量。视图是 Claude-only,窗口为 5h / 7d / 各周窗口(如 `Fable`)。

| 键 | 行为 |
|---|---|
| `↑↓` / `k j` | 选择账号(到顶/到底即停,与 local 面板一致) |
| `enter` | 切到选中账号——**经 master 指定账号租借**,写入 `access` + 哨兵 refresh |
| `r` | 刷新用量——**调 master 的 `POST /v1/usage/refresh`**,节流在服务端 |
| `esc` | 关闭 |

local 面板的 `d`(删号)和 `m`(不自动切)**刻意没有**:这两个键写的是账号库,而账号库在 master 上,不是这台机器的东西。

### worker 的「切号」不是本地切号

worker 没有真实 token,只有租约,所以"切到账号 X"的语义是**请求 master 专门租借 X**:请求体多带一个 `preferredAccountIdPrefix`,master 解析后走与定时租约完全相同的下发路径(选号 → 刷新 → INV-CLOUD-4 视界校验 → 下发)。

- **送的是 id 前 8 位,不是完整 id。** 因为面板是用 `UsageAccountView` 渲染的,而它只带前缀(`/v1/usage` 免鉴权,不该公布完整 id)。前缀→账号的解析发生在**要 pool key 的** `/v1/lease` 上。
- **不满足就拒绝,绝不换一个给你。** 前缀查无此人、撞车(命中多个)、账号正在冷却、账号 `needsReauth`,四种情况一律 `409` + `refused` 字段,worker 按原因给出对应中文提示。**换一个账号糊弄过去**会让运维把下一轮用量记到错误的订阅上。
- **`excluded`(不自动切)是可以手动切进去的。** 这个标记的字面意思就是"不要**自动**切到它",手动点名恰是它不适用的场景。
- **worker 侧也校验一次。** master 若版本较旧会**静默忽略**未知字段并按排名返回另一个账号,所以 worker 会核对下发的 `accountId` 是否匹配自己点名的前缀,不匹配就拒绝写入。两端都守,半升级的池子也不会切错号。
- **切完不粘。** 本池刻意没有 worker→账号亲和性(见 `scheduler.ts` 顶部那条禁令),所以下一次续租仍按用量排序,可能把你切的号换走——成功提示里会明说这件事,而不是让你当 bug 发现。

### `r` 的两个细节

- **worker 不自己轮询上游。** `r` 只是让 master 跑一轮,所以 N 个 worker 一起按,也被 master 那**一份**服务端节流覆盖(30 秒),不会放大成 N 倍 `/api/oauth/usage`。
- **提示画在面板里,不用 toast。** 实测:对话框开着时弹 toast,双宽字符会被对话框重绘抹掉——中文只剩空白(`master  28`),而 ASCII 还在。`r` 故意不关面板,所以它的结果必须画在面板内;`enter` 会先关面板再弹 toast,那条路径的中文是正常的。

## 一条硬规矩

**纳入池子的账号,在池外不能再有任何刷新者。** 旧机器上残留的登录、第二个 master,都算。

Anthropic 的 refresh token 是一次性并且轮换的,而且一次刷新还会立刻作废上一枚已签发的 access token——所以池外的第二个刷新者不仅会打断 refresh 链(败者拿到 `invalid_grant`,账号需重新登录),还会**当场击毙所有在外的租约**。
