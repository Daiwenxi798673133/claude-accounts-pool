# cloud 模式详解(账号池)

把一批 Claude 账号做成跨机器共享的池子:一台 **master** 持有全部 refresh token 并作为**唯一的刷新者**,多台 **worker** 向它租借短时效 access token。配置写法与运维步骤见 [README](../README.md);架构决策的完整记录与实测证据见 [design/cloud-mode-adr.md](design/cloud-mode-adr.md)。

## 三种模式与职责划分

行为由 `tui.json` 里的**插件参数**决定,**不配置参数就是 `local`**——也就是上游那套单机行为,一切照旧。

| 模式 | 跑在哪 | 做什么 |
|---|---|---|
| **`local`**(默认) | 你自己的机器 | 上游原有行为:`/usage`、`/stats`、多账号切换、撞限自动切号、token 保活。详见 [local-mode.md](local-mode.md) |
| **`cloud-master`** | 一台中心主机 | 持有**全部**账号的真实 refresh token,是**整个系统里唯一的刷新者**;保活所有 token、按用量挑最空的号、通过 HTTP 把短时效 access token 租借给 worker。**它自己不跑推理** |
| **`cloud-worker`** | 每个工程师的机器 | **永不持有可用的 refresh token**;向 master 租借 access token 并在过期前续租。撞 **429** 时由 master 换一个账号、自动续接那一轮;租来的 token 撞 **401** 则属于租约失效(master 刷新某个账号会当场作废它在外的 access token),这时 worker 重租**同一个**账号,不冷却也不换号。ChatGPT 仍走本地,不纳入池子 |

命令也是**按模式注册**的:`local` 有 `/usage` 和 `/stats`,`cloud-worker` 只有一个精简版 `/usage`(见下文),而 **`cloud-master` 一个命令都不注册**——它没有 `/usage` 也没有 `/stats`,master 端要看用量请打开 web 看板。

master 与 worker 的分工再拆细一层:

| | master | worker |
|---|---|---|
| refresh token | 持有**全部**账号的真实 refresh | **永不持有可用的 refresh** |
| 刷新 | **唯一的刷新者**,单飞(同账号并发只发一次刷新请求) | 从不刷新,只领租 |
| 选号 | 按各账号订阅用量挑最空的,维护冷却状态 | 不参与选号 |
| 撞限检测 / 续接 | 看不到(429 只在 worker 的会话事件里) | 检测 429、上报 master、拿到新号后续接那一轮 |
| 推理 | 不跑 | 跑 |
| ChatGPT | 不纳入池子 | 仍走本地 codex 插件 |

## worker 的 `auth.json` 里那个奇怪的 refresh 是什么

如果你在 worker 上打开 `auth.json`,会看到 `anthropic` 条目的 `refresh` 是一串**明显不像 token 的常量**。这是故意的。

实测发现 **OpenCode 会静默丢弃缺少 `refresh` 字段的 `anthropic` 条目**:带一个假值时 `opencode auth list` 报 `1 credentials`,去掉该字段就变成 `0 credentials`,而且退出码 0、一句报错都没有。所以租约只能写成 `access` + `expires` + 一个**可识别的哨兵字符串**。

账号库的收录路径会**按值拒绝**这个哨兵,因此它永远不会被误当成真凭据存起来、也不会被回传给 master。这个守卫是按值判断而非按模式判断的,所以在 local 模式下这条分支永远不会被走到。

## 为什么租约的到期时间比账号 token 的真实到期更早

master 会在账号 token 即将过期前把它刷新掉,而**这次刷新会立刻作废上一枚 access token**(实测:旧 access 刷新前 `200`,刷新后同一枚 `401`)。这违反常规 OAuth 2.0 语义,却是实际行为。

所以 master 下发租约时,故意把到期时间**封顶在自己动手刷新的那一刻之前**,worker 再提前一段续租——这样 worker 永远在 master 轮换之前就换到了新 token。若租约视界已经落到过去,master 直接拒绝发放(返回"暂无可用账号"),而不是下发一枚到手即死的 token。

万一 worker 仍然握着被轮换掉的 token(时钟偏移、笔记本休眠唤醒),它会把 `401` 当作"租约被轮换"处理:立刻重新领租并续接那一轮,**不会**把这个健康账号误判成撞限而冷却掉——把 401 误 route 进限流路径会白白冷掉一个好号、削减池子容量。

## 为什么内部标识符仍然叫 `claude-accounts-usage`

包名改成了 `claude-accounts-pool`,但代码里的内部标识符**一律保持原样**。这是刻意的,**请不要"顺手统一"**:

- **跨进程锁文件名 `claude-accounts-usage.lock`** —— 这把锁防的正是"两个插件实例并发轮换同一张一次性 refresh token"。如果某台机器上新旧两个包同时存在而锁名不同,**互斥会直接消失**,而这正是整个项目要避免的那个失败。
- **OpenCode 的 KV 命名空间** —— 冷却状态这类跨会话数据存在里面,改了会全部孤立:master 重启后会读不到自己上一轮写下的东西,而不是报错。
- **日志服务名** —— 所以 [internals.md](internals.md#日志与排查) 里那条 `grep` 命令不变。
- **租约哨兵字符串** —— 改了两个版本就互不认识对方的租约。

## `workerId` 只是一个日志标签

`cloud-worker` 的配置里有一个 `workerId`,它**不是凭据**,请不要当凭据用。master 这一侧没有任何东西认证它:worker 在请求体里自报一个字符串,master 原样记进日志,仅此而已。它的全部作用是让 master 的日志能把一条租约归到某台机器上,便于回答"这个号是谁在用"。

服务端只对它做一件事:按 `^[A-Za-z0-9._-]{1,64}$` 校验,不匹配直接 `400`。这道校验管的也不是身份,而是**日志的完整性**——这个字段是这条线上唯一会落进日志文件的调用方输入,一个控制字符就能伪造出一整行换行、往运维的日志里塞进假条目,而一个无长度上限的字符串能让单个请求把磁盘写满。字符类比主机名宽(大小写都留着),是为了不让一台已经在跑的 worker 被一条它从没同意过的收窄挡在门外。

## 只有一条东西挡在 master 前面:绑定地址

master 的 HTTP 端口**没有任何应用层鉴权**,一条路由都没有。能连到这个端口的人就能租到 token、能读到全池名册、能往池里加号。所以**绑定地址就是全部的访问控制**:`hostname` 指向哪个网络接口,谁能用这个池子就由那个网络决定。本项目的部署里绑的是 Tailscale 地址(形如 `100.64.0.36:8787`),访问控制实际上外包给了 tailnet 的成员资格。

`hostname` 省略时默认 `127.0.0.1`,想更宽必须在 `tui.json` 里显式写出来——这个默认值是**故意**挑成"不可能泄露的那一个",让"把池子开给别的机器"成为一次显式动作,而不是一次疏忽。

在 lease 前面单摆一道 bearer token 解决不了这个问题:那把凭据自己也得有个发放入口,而**发放入口又该被谁挡**,是同一个问题挪高一层。真正的边界只有一道,不会因为多摆一层而变成两道。完整的取舍与代价见下文[「为什么整台 master 都不做鉴权」](#为什么整台-master-都不做鉴权)。

## 一条命令把 worker 配好

把一台机器并进池子只需要一条命令,直接粘进那台 worker 的终端:

```bash
git clone --depth 1 https://github.com/Daiwenxi798673133/claude-accounts-pool.git ~/.claude-accounts-pool \
  && cd ~/.claude-accounts-pool && bun install && bun run build \
  && bun run scripts/configure-worker.ts --master <MASTER_URL> --worker <LABEL>
```

`bun` 是**硬前置**:`dist/` 不入库,worker 必须本机构建一次。`configure-worker.ts` 写进配置的插件路径是**从脚本自己的位置推出来的绝对路径**(不是 cwd,也不留 `~`),指向刚构建出的那个 `dist/tui.js`。

它改的是这台机器上**别人已经配好、并且正在用**的 OpenCode 配置(`$XDG_CONFIG_HOME/opencode`,没设就是 `~/.config/opencode`),所以整个脚本是围绕"**不要弄坏它**"排的:

- **只保证两件事**:`@ex-machina/opencode-anthropic-auth` 出现在 opencode 配置的 `plugin` 数组里;本插件的 `["<clone>/dist/tui.js", {"mode": "cloud-worker", "masterUrl": …, "workerId": …}]` 元组出现在 `tui.json` 的 `plugin` 数组里。ex-machina **以任何形式出现都算数**,包括 `…@1.2.3` 这样的版本锁——重写别人的版本锁不是这个脚本的事,而再追加一份没锁的会把插件装载两遍。
- **绝不触碰、也不重排别人的条目**:插件的加载顺序是可观测的。我们自己那条(按**形状**认:路径带 `claude-accounts-pool` 且以 `dist/tui.js` 或 `tui.tsx` 结尾——clone 会换机器,用户也可能直接指源码)是**就地替换**,不是追加。
- **语义没变的文件一个字节都不碰。** 改动判定拿的是**规范化之后**的两份 JSON 比对,不是比原文,所以重跑一遍是真正的 no-op,也不会顺手把别人的缩进"修正"掉。
- **先探 `.jsonc` 再探 `.json`**(前者才是 OpenCode 自己发的那份的名字),两个都不存在时新建 `.json`。
- **写前备份**(`<原文件>.bak-<时间戳>`)、**原子写**(先写同目录临时文件再 rename,权限 `0600`),并且先把 diff 打在终端上再动手。`--dry-run` 只打 diff,不备份也不写。

四种情况它**拒绝写**,改为把该手工粘贴的 JSON 打出来(退出码 `1`)。而且**两个文件是一起规划、一起写的**:先攒齐所有问题再报,绝不留下一台配了一半的机器。

| 拒写条件 | 为什么不猜 |
|---|---|
| 文件解析不出 JSON | **`.jsonc` 里真写了注释就属于这一类**——脚本用的是 `JSON.parse`,不认注释 |
| `plugin` 存在但不是数组 | 这份配置我们看不懂,看不懂就不能改 |
| `.json` 与 `.jsonc` 同时存在 | 写哪一份都会让机器上留着两份配置,而且无从判断谁生效,得先由人删掉一份 |
| 发现旧包 `claude-accounts-usage` 的条目 | 两个插件**绝不能并存**,丢哪一个是人的决定,不是脚本的 |

参数缺失、`--master` 不是 http(s) URL 之类的用法错误退出码是 `2`,并且**一次报全**所有缺的 flag——操作者粘的是别人给的命令,一次发现一个要求本身就是个 bug。写完要**完全退出并重开** OpenCode。

## 只读用量看板

master 在**同一个端口**上多挂几条路由,给运维一个能看**全池**用量的出口——worker 和 local 模式都没有这个视角。名字里的"只读"如今只覆盖前两条,后面四条都会写(见文末的硬约束)。

| 路由 | 方法 | 鉴权 | 内容 |
|---|---|---|---|
| `/v1/usage` | GET | **免鉴权** | 全池每个 anthropic 账号的 label、id 前缀、各窗口利用率与 `resetsAt`、冷却状态、token 到期、`needsReauth` / `excluded` |
| `/` | GET | **免鉴权** | 一个零依赖的 HTML 页面,自己去拉 `/v1/usage` 并渲染(进度条 + 倒计时)。页面本身不含任何数据 |
| `/v1/usage/refresh` | **POST** | **免鉴权** | 页面上「刷新」按钮打的那一发:立刻跑一轮采集,再返回采集结果。**服务端 30 秒最小间隔**,被拒时返回 `429` + `Retry-After` + `retryAfterMs` |
| `/v1/account/authorize` | **POST** | **免鉴权** | 「添加账号」第一步:生成一条 Claude PKCE 授权链接,返回 `{url, pendingId, expiresAt}`。verifier 只留在 master 内存里,浏览器只拿到 `pendingId` |
| `/v1/account/add` | **POST** | **免鉴权** | 第二步:用运维粘回来的 code 换取真实 token,查 profile,写进账号库。返回 `{idPrefix, label, existing}`,**不含任何 token** |
| `/v1/account/delete` | **POST** | **免鉴权** | 「删除账号」:按 `{idPrefix, label}` 把一个账号移出账号库。**两个字段都必填**——前缀定位、label 是确认。前缀命中多个直接拒(`409 ambiguous`),label 对不上也拒(`409 label-mismatch`),删之前先把这条记录单独备份到 `claude-accounts.json` 同目录 |

关于刷新按钮有两处不是随手写的:

- **必须是 POST。** 这是唯一一条会向机器外部发请求的看板路由(它让 master 逐个账号去调 Anthropic),而浏览器、链接扫描器、聊天软件的链接预览都会**主动 GET** 它们看到的 URL。做成 GET 就意味着"把看板链接贴进群里"能触发全池上游流量。
- **节流是全服务端共享的,不是按调用方。** 它保护的是 master 那一个出口 IP,所以别人按过之后你也要等——这正是正确行为。它复用 `usagePoller` 自己的 `tickOnce`,因此顺带继承了重入防护、账号间 500ms 间隔和单账号 429 冷却。

### 为什么整台 master 都不做鉴权

**整台 master 上一条带鉴权的路由都没有。** `/v1/lease` 和 `/v1/ratelimit` 也不例外——它们和 `/v1/usage`、看板首页、「添加账号」站在完全相同的位置上:能连到端口就能调。这里没有"要紧的路由"和"顺带的路由"之分,只有一条边界,而它不在这个进程里。这是**池主人的显式决定**,推翻了本功能最初「看板不应裸奔」的要求。

理由是一道绕不开的循环。任何一把应用层凭据都得有个发放入口,不然每加一台机器都要人工传一次密码,一个池子还没用起来就先变成了一件行政工作;而**发放入口本身又该被谁挡?** 挡它需要另一把凭据,那把又需要再挡一次。这个循环唯一的出口是把判断交给网络层。既然最终还是网络层说了算,在它前面再摆一道就只剩"看上去有防护"这一个作用,而它实打实的代价是让"打开网页点一下"不再成立——那正是池主人不要的东西。**多摆一层不会把一道边界变成两道,只会让人误以为有两道。**

代价是真实的、明知而接受的,不打算含糊过去。**凡是能连到这个端口的人**:

- **能读到整个池子的名册**,包括每个账号的**邮箱**、各窗口余量、冷却状态。账号 id 只给前 8 位,但邮箱是全的。
- **能往池里加号**——只要他有自己的 Claude 账号。反过来说,他加进来的是他自己的号。
- **能把号删出池子**——前提是他照着页面把那个账号的邮箱一字不差地打出来。这是这套路由里唯一一个**破坏性**动作,见下面单独的一节。
- **能租走一枚活的 access token**,也就是能直接用池子里的号跑推理。这一条最要紧:**能连到这个端口,基本等于能用这个池子**。
- **能报一次假的撞限**,把某个健康账号冷却出选号队列,削掉一截池子容量。

**能收窄的只有绑定地址**,别无他法——默认 `127.0.0.1`,想更宽必须在 `tui.json` 里显式写 `hostname`。本项目的部署里绑的是 Tailscale 地址,于是"谁能用这个池子"这个问题的真正答案是"谁在这个 tailnet 里"。把这句话当成部署前的检查项:**在决定 `hostname` 写什么的那一刻,你就把访问控制策略定完了**。

### 「添加账号」用什么代替鉴权

纳管入口是**看板上第一处会写的路由**,所以它值得单独说一遍:原先"纯只读"那条承诺到此为止(下面的硬约束列表已相应修订)。既然前面没有任何鉴权挡着,挡住它的只能是三道**有界性**,都在 `src/constants.ts`:

| 约束 | 值 | 挡住什么 |
|---|---|---|
| `ONBOARD_MAX_PENDING` | 4 | 内存。匿名狂刷 `/authorize` 的代价是**常数**,不是慢性泄漏——满了就淘汰最旧的 |
| `ONBOARD_MAX_ATTEMPTS` | 3 | 单个会话能引发的**上游 POST 次数**。用完即焚,必须重新拿链接 |
| `ONBOARD_ADD_MIN_INTERVAL_MS` | 3 秒 | 上游 POST 的**速率**。防止一串慢速请求变成打向 token 端点的 400 风暴——那会让 master 的出口 IP 被封,连坐全池的 refresh |

这三道界**都不声称匿名者加不了号**。他加得了,见上一节。它们保证的只是:加号这件事不能被拿去把 master 的内存吃光,或者变成一串打向 Anthropic token 端点的风暴。

还有两点是刻意的:

- **verifier 绝不出机器。** 授权链接里带的是 challenge(verifier 的 SHA-256),浏览器只拿到一个不透明的 `pendingId`。所以就算有人截走了 code,也换不到 token——**只有 master 换得到**,这正是"master 是全系统唯一持有 refresh token 的人"这条性质的延续。
- **新链条直接写账号库,不过 auth.json。** 这条链是我们自己刚换来的,池外没有第二个持有者,所以不存在 `makeOnboardingCapture` 那边必须回避的轮换竞争;走 auth.json 反而要等 keeper 下一个 tick(最多 5 分钟)才入池,对话框只能干等或者撒谎。

### 「删除账号」凭什么比「添加账号」更严

同一个免鉴权门槛之下,**加号和删号的风险并不对称**,所以两条路由的防线也不该一样:

- **加号是增量的**,最坏结果是池子里多一个号——那个号还是对方自己的。
- **删号是破坏性且不可撤销的**:账号记录里的 `refresh` 是这条链在世上的**唯一一份**,Anthropic 不会补发,删掉就只能重新走一遍 OAuth 授权。

于是删号这条路上摆了四样东西,少一样都不行:

| 防线 | 在哪 | 挡住什么 |
|---|---|---|
| 弹窗里**重新打一遍邮箱** | `dashboardHtml.ts` | 反射性的一键误删。选中的那行和输入框必须**完全相等**才允许提交 |
| 服务端**再核一次 label** | `accountRemove.ts` | 上面那道要是只在浏览器里,一个直接打的 POST 就绕过去了。label 随请求一起送,master 拿它跟前缀解析出的那条记录再比一次 |
| 前缀**命中多个就拒** | `accountRemove.ts` | 沿用 `pickPreferred` 的 `ambiguous` 语义。切错号可以再切回来,删错号不能 |
| 删之前**先落一份备份** | `accounts.ts` 的 `backupRemovedAccount` | 无法撤销这件事本身。备份写在 `claude-accounts.json` 同目录、`0o600`、**一次删除一个文件**(不覆盖上一份),没有任何自动清理 |

两点刻意的取舍:

- **是真删,不是软删。** 打 `excluded: true` 看着更安全,但 `excluded` 早有确定含义——"不参与自动切号",而 `pickPreferred` **仍然会服务**被标记的账号(运维在 worker 面板上手动点它是合法的)。拿它当删除会让这个标记同时表示两件事,而"我以为它已经不在池子里了"是最不该出现的误解。真删 + 备份,语义是干净的。
- **不做节流。** 加号的三道有界性是为了保护 master 的出口 IP(它会打 Anthropic 的 token 端点),删号一个外部请求都不发。而能连到这个端口的人本来就能直接租走 token——给删号加一道节流,防不住任何真正想删的人,只会让运维在真要删的时候多等。

### 几条实现上的硬约束

- **绝不输出 token。** 载荷类型里根本没有能放 `access` / `refresh` 的字段,想泄露必须先加字段——那正是 review 会看到的地方。账号 id 只给前 8 位。**这条在没有鉴权的前提下更要命**:前面什么都没挡着,页面的载荷就是这个池子对外暴露的全部内容。页脚那句「本页不展示任何 token 明文」因此是一条硬承诺,不是一句客套。
- **不新增任何对外部 API 的轮询。** 看板读的是 `usagePoller` 已经在跑的那份快照,所以刷新页面**不可能**触发 `/api/oauth/usage`(它的 429 会持续好几分钟,且按出口 IP 连坐)。既然一条路由都不设防,这条也是**匿名请求打不动这个池子**的保证。<br>**「添加账号」是这条的唯一例外**,而且是有界的例外:它只在运维粘回 code 时打一次 token 端点(不是 usage 端点),次数被 `ONBOARD_MAX_PENDING × ONBOARD_MAX_ATTEMPTS` 封顶、速率被 `ONBOARD_ADD_MIN_INTERVAL_MS` 封顶。**光看页面、光点「添加账号」不会产生任何上游流量**——生成链接是纯本地的 crypto。
- **master 刚重启的 5 分钟内看板是空的。** `usagePoller` 用 `setInterval`,首轮采集要等一个 `MASTER_USAGE_POLL_INTERVAL_MS`(5 分钟),此时 `at` 为 `0`、`stale` 为 `true`,页面会明说"尚未完成任何一轮轮询",而不是画一堆 0%。
- **陈旧判定由调度器给。** 阈值就是调度器自己停止按用量排序的那条线(两个轮询周期),所以看板亮绿灯的时刻和调度器仍然信任这些数字的时刻**天然一致**;快照陈旧时页面顶部会红字明示,而不是继续画一根自信的绿条。
- **没拿到快照的账号显示「本轮无数据」,不是 0%。** 轮询失败的账号被 poller 直接省略,把这种缺失渲染成 0% 会让运维一眼看到"最空的号"其实是"最不知道的号"。
- **绑定地址沿用 lease server 的约定**:默认 `127.0.0.1`,想更宽必须在 `tui.json` 里显式写 `hostname`。这个端口本来就在发活的 access token,看板不降低它的默认。
- **会写账号库的有两处:「添加账号」和「删除账号」,两处都不切号。** 加号只往账号库里追加一条记录;删号只摘掉一条记录(顺带清掉指向它的 activeId),都不改"谁在用"。<br>*(这句话被推翻过两次。原文是无条件的「纯只读」,加入纳管入口后收窄成「会写的只有添加账号一处,不切号、不删号」,如今删号入口落地,连"不删号"也不再成立。痕迹留着,是因为一句好听但已经不对的承诺,比没有承诺更危险——这也是为什么每次都是改写这句,而不是补一句新的在后面。)*

## worker 的 `/usage`:选号、切号、刷新

cloud-worker 上的 `/usage` 渲染的是 master 那份同样的快照(经 `GET /v1/usage`),**worker 自己从不调 Anthropic 的 `/api/oauth/usage`**——否则 N 个 worker 就是 N 倍上游流量。视图是 Claude-only,窗口为 5h / 7d / 各周窗口(如 `Fable`)。

| 键 | 行为 |
|---|---|
| `↑↓` / `k j` | 选择账号(到顶/到底即停,与 local 面板一致) |
| `enter` | 切到选中账号——**经 master 指定账号租借**,写入 `access` + 哨兵 refresh |
| `r` | 刷新用量——**调 master 的 `POST /v1/usage/refresh`**,节流在服务端 |
| `esc` | 关闭 |

local 面板的 `d`(删号)和 `m`(不自动切)**刻意没有**:这两个键写的是账号库,而账号库在 master 上,不是这台机器的东西。

### worker 的「切号」不是本地切号

worker 没有真实 token,只有租约,所以"切到账号 X"的语义是**请求 master 专门租借 X**:请求体多带一个 `preferredAccountIdPrefix`,master 解析后走与定时租约完全相同的下发路径(选号 → 刷新 → INV-CLOUD-4 视界校验 → 下发)。

- **送的是 id 前 8 位,不是完整 id。** 因为面板是用 `UsageAccountView` 渲染的,而它只带前缀(`/v1/usage` 免鉴权,不该公布完整 id)。前缀→账号的解析发生在 `/v1/lease` 上。
- **不满足就拒绝,绝不换一个给你。** 前缀查无此人、撞车(命中多个)、账号正在冷却、账号 `needsReauth`,四种情况一律 `409` + `refused` 字段,worker 按原因给出对应中文提示。**换一个账号糊弄过去**会让运维把下一轮用量记到错误的订阅上。
- **`excluded`(不自动切)是可以手动切进去的。** 这个标记的字面意思就是"不要**自动**切到它",手动点名恰是它不适用的场景。
- **worker 侧也校验一次。** master 若版本较旧会**静默忽略**未知字段并按排名返回另一个账号,所以 worker 会核对下发的 `accountId` 是否匹配自己点名的前缀,不匹配就拒绝写入。两端都守,半升级的池子也不会切错号。
- **切完不粘。** 本池刻意没有 worker→账号亲和性(见 `scheduler.ts` 顶部那条禁令),所以下一次续租仍按用量排序,可能把你切的号换走——成功提示里会明说这件事,而不是让你当 bug 发现。

### `r` 的两个细节

- **worker 不自己轮询上游。** `r` 只是让 master 跑一轮,所以 N 个 worker 一起按,也被 master 那**一份**服务端节流覆盖(30 秒),不会放大成 N 倍 `/api/oauth/usage`。
- **提示画在面板里,不用 toast。** 实测:对话框开着时弹 toast,双宽字符会被对话框重绘抹掉——中文只剩空白(`master  28`),而 ASCII 还在。`r` 故意不关面板,所以它的结果必须画在面板内;`enter` 会先关面板再弹 toast,那条路径的中文是正常的。

## 一条硬规矩

**纳入池子的账号,在池外不能再有任何刷新者。** 旧机器上残留的登录、第二个 master,都算。

Anthropic 的 refresh token 是一次性并且轮换的,而且一次刷新还会立刻作废上一枚已签发的 access token——所以池外的第二个刷新者不仅会打断 refresh 链(败者拿到 `invalid_grant`,账号需重新登录),还会**当场击毙所有在外的租约**。
